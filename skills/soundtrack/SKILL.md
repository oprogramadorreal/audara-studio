# soundtrack

Turns what a video has (a song, a script, or nothing yet) into audio files plus the timing data the picture syncs to. Every path ends the same way: audio in `videos/<video>/audio/`, and `videos/<video>/data/audio.json` (beats, downbeats, sections, loudness envelopes, onsets, cues) and/or `data/words.json` (sung or spoken words with their times), in the formats the code-video engine reads. Outside an audara project, `--out <dir>` puts them in `<dir>/audio/` and `<dir>/data/` instead. `<skill>` is this skill's folder (other paths are the project's); every script runs with uv and has `--help` with examples.

## Fixed
- **Spending waits for a yes.** Before any generation that costs credits, say what it will make (characters, length, estimated credits, voice, model) and wait. The scripts refuse to spend without `--yes` and print that plan instead. For music, show the free composition plan first; for a voice, approve one short block before the rest.
- **The key stays in the environment** (`ELEVENLABS_API_KEY`): never in a file, a log or a command line.
- **Generated audio is an asset, not a build step.** Generate once, keep the file and the request record beside it; the scripts regenerate only when the request changed, and renders never call the API.
- **Licenses are respected:** say what a voice, a model or a plan allows before relying on it, and again when handing over audio for a client or a monetized video, naming the account's plan as the scripts print it (free ElevenLabs plans are non-commercial; some alignment models are non-commercial too).
- **Numbers are measured, not claimed.** Report what the scripts measured.

## Which path
- **The user's song**: `uv run <skill>/scripts/beats.py <song> --video <video>` gives beats, downbeats, sections, envelopes and onsets, on a fitted grid when the tempo is steady. Pass on its time line as printed: never tell anyone to shift the times. Words on screen: `uv run <skill>/scripts/align.py song <song> --lyrics lyrics.txt --video <video>` (heavy: downloads models once, to a user-level cache).
- **A window of the song**, for a video shorter than it: `uv run <skill>/scripts/beats.py window --video <video> --from <start> --to <end> [--fade <seconds>]` cuts `audio/<song>-window.wav` from the song's own samples and writes the window's data in video time from the whole song's, which stays in `data/song/` (analyzed first when missing). An end that misses a downbeat moves to the nearest one unless you pass `--exact`, so tell the director the length it prints; it warns, with the fix, when an end cuts a sung word, and prints the `video.json` edit.
- **A script to narrate**: write it with the user, keeping what is said apart from what is shown (a `--say` map: "SQL" said as "sequel"). `uv run <skill>/scripts/eleven.py tts script.txt --video <video> --voice <id>` prints what it would make and cost; after a yes, `--only 1 --yes` makes a one-block voice test; once the director approves the voice, `--yes` makes the rest. One paragraph is one block; the picture cuts in the silences between blocks. Its phrase edges are measured and moved onto the sound in the same run. Choose the voice with the director from `eleven.py voices`, whose preview links cost nothing to play.
- **Music**: `eleven.py music plan` (free) with sections that match the edit (`--sections` start times with `--length`, or `--lengths`) or the narration's chapters (`--from-narration`); after approval, `eleven.py music compose --plan <file> --takes 2 --yes`, then `--pick K` and the `beats.py` command it prints (it keeps the plan's section times exactly). A library track the user owns can beat a generated one. Music you synthesize yourself is fine too: keep the seeded script beside the audio, write its grid and cues with `beats.py grid` (scenes find a cue with `audio.cue('hit')`), and measure it like any mix.
- **Effects**: `eleven.py sfx "<prompt>" --n 4` screens the candidates by analysis before anyone listens; place each one by its measured onset.
- **Mix**: `uv run <skill>/scripts/mix.py build --video <video>` mixes from `videos/<video>/mix.json` into `mix.wav` plus `music-only.wav` at delivery loudness, and prints what video.json still needs (`"audio": "audio/mix.wav"` and the mix's `duration`); `mix.py measure <file>` reports what a listener hears (K-weighted loudness per section, the build into each hit and the hit against it, a phone-speaker check). Say where the phone column disagrees with full range. A brief that wants a gentler build or hit sets `build_lu` or `hit_lu` in mix.json, with the reason.
- **Word timings against the sound**: narration from `eleven.py tts` is snapped already. Any other voice (the user's recording, a stand-in) is levelled as eleven.py levels narration (-16 LUFS, true peak at or under -1 dBTP, as `mix.py measure` reads them), then `uv run <skill>/scripts/align.py check <audio> --words videos/<video>/data/words.json --fix`; a generator you write ends with that check, so a re-run stays on the sound. On a song, `check` validates the structure only, and `align.py song`'s review list and sheets are the check.
- **No key, or no spending yet**: run the command anyway (`eleven.py tts <script>`, or `music plan` with its length): without a key it spends nothing and prints the cost and what a key would add. Say both in one line of your reply, name the free paths, then go on with the one that fits unless the user picks another: the user's own recording; a local open-source voice as a stand-in (state its license and that it will be replaced: scenes find words by their text, so they keep their sync when the final voice arrives); music you synthesize (above); or a silent placeholder (`"audio": null` and a `duration` in video.json). The picture never waits for the sound.

If a sandbox stops uv from writing its own cache, set `UV_CACHE_DIR` to `.audara-cache/uv` inside the project (git-ignored), or to a short folder such as `C:\uvc` when the project's path is long (uv fails past Windows' 260-character paths), and say in the last reply where it is, its size and that it can be deleted.

## Show the work
After each step, and in the last reply itself (not only in a file or an earlier message): every file you wrote, the data file first; the numbers the scripts measured (a song: tempo, fit residual, first and last beat; a voice: duration, LUFS, true peak, worst word edge; music: length, hit time and contrast, the build into it, LUFS, true peak); the review images in `out/<video>/` (a beat sheet, a loudness curve); what nobody has listened to yet; and, when the preview runs, `?v=<video>&t=` links to the moments that matter.
